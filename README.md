## 一、建立独立 Python 环境

需要 Python 3.12，当前启动命令支持 macOS/Linux。

```sh
python3.12 -m venv .venv
```

初始化和配置命令仅使用 Python 标准库，不会安装或升级任何成员。
先装服务、共享搜索和本地工具需要的基础依赖：

```sh
.venv/bin/python -m pip install -r release/legion-service/requirements-core.txt
```

这一步应在独立虚拟环境中串行执行，不能在其它依赖安装进行中并发运行。
不要使用 `--system-site-packages`、全局 pip 或从旧开发机复制 `.venv`，
否则看似独立，实际上可能通过旧 editable 安装继续读取原工程。
基础依赖已在全新 macOS/Python 3.12 虚拟环境中从公开 PyPI 实际安装，
并通过依赖一致性检查；这不是 Linux/Windows 或全部成员的安装验收。

需要原 Auto/DeepAgents Python 依赖时，再按需安装：

```sh
.venv/bin/python -m pip install -r release/legion-service/requirements-auto.txt
```

原 `requirements.txt` 仍保留为两组依赖的聚合入口。
它们不安装各家的原生 CLI、浏览器、模型权重或账号，也不自动启用旧 Auto 引擎。
保留可选依赖不是把军团缩成一家；成员仍走原目录和原安装入口，分别配置授权、验证运行。
本阶段没有跑可选依赖的完整安装。

### 原生成员入口

下面的初始化示例使用 Codex 原生 CLI；其他成员保留各自的配置与接入入口。
在准备启动服务的同一环境中，
先确认 `codex --version` 真正能执行，不能只检查是否存在同名脚本。
如机器上有多个同名入口，只在这个服务的启动环境中调整 `PATH`，
不要替换用户现有全局命令或借用其他环境的登录配置。
CLI 能启动不等于模型授权有效，真实请求仍需下文的显式模型配置。

## 二、初始化自己的本地实例

选择一个**不在源码仓库内的、只由自己访问的数据目录**。示例：

```sh
.venv/bin/python -I meyo.py init --state-dir "$HOME/.local/share/meyo-legion" --user my-user --port 8000
```

此命令只创建本机数据目录和现有个人认证格式的首个身份，不创建远端账号、不向模型发请求。
同一目录再次初始化不会更换 Token 或删除历史；不同用户/端口或不认识的已有内容会拒绝覆盖。
登录凭证保存在该目录的 `login-token.txt`，文件权限为0600。命令只打印路径，不打印凭证。

不要把整个实例目录放进 Git、共享网盘或公开文件服务器。

## 三、配置自己的模型

先把本人获准使用的模型密钥放入仅本人可读的文件（权限0600），不要把密钥直接写在命令参数里。

```sh
.venv/bin/python -I meyo.py configure-model \
  --state-dir "$HOME/.local/share/meyo-legion" \
  --model "本人提供方实际支持的模型ID" \
  --base-url "https://本人提供方的API地址/v1" \
  --api-key-file "/绝对路径/仅本人可读的密钥文件"
```

配置在本机实例的 `secrets/model.json` 中原子保存。
该阶段接通的是 **Codex 的显式 Responses 提供方**；地址必须真实支持 Responses，
不能把 Chat Completions 接口当作相同协议，也不自动替换个人原生登录配置。
其它成员保留原接入机制，不能据此称它们已经获得或验证了这个模型授权。

密钥错误、网络受限或提供方不兼容，仍需真实调用才能确认。
“配置已保存”不等于“模型已验证”。

## 四、检查并启动

```sh
.venv/bin/python -I meyo.py check --state-dir "$HOME/.local/share/meyo-legion"
.venv/bin/python -I meyo.py serve --state-dir "$HOME/.local/share/meyo-legion"
```

也可使用 `make check STATE=/绝对路径/实例` 和 `make run STATE=/绝对路径/实例`。

- 只监听配置中的 `127.0.0.1:端口`，不自动发布到公网。
- 服务仍是原 `server.py`，没有增加另一个后台调度器或自动重启器。
- 首次打开页面，使用“个人授权”输入本实例 `login-token.txt` 中的凭证。
- 模型未配置时可以打开页面，状态如实显示未就绪；不会使用环境里的公司凭据补齐。
- `HOME`、原生 Codex 状态、会话、上传、进程登记、成员源码与运行依赖目录均位于本实例。
- 模型凭据、旧的 `PYTHONPATH`、个人/公司 Token 和旧实例路径不会从启动Shell自动继承。
  PATH、语言和显式TLS/代理设置仍可用于正常运行。
- 服务重启再次从配置文件读取同一身份和模型绑定，不需要重复初始化。
- 配置文件的改动在下一次 `check` 或新启动的 `serve` 中生效；
  已经运行的服务需正常重启，当前入口不提供热更新或实时密钥撤销。
- 换模型/地址/密钥后，已有原生断点的绑定校验仍生效；不能把旧历史偷偷送到新提供方。
- `check` 不联网、不调用模型；`serve` 仍保留原服务的任务恢复和后台版本查询，
  不能把它当成离线探针。自动成员更新/安装已用原开关关闭，启动不会批量安装成员。

### 把自己的长期产品方向交给原续作机制

研究世界上的好作品、保留原意图、动态协作、完整交付、看图返工和经验复用，
不应只写在宣传页里。本包提供[可编辑的产品方向示例](docs/examples/pilot-goals.md)，
但**安装不会默认采用示例，也不会从旧仓库或启动 Shell 偷带个人指令**。
确认或编辑其中的内容后，明确采用：

```sh
.venv/bin/python -I meyo.py configure-goals \
  --state-dir "$HOME/.local/share/meyo-legion" \
  --file "/绝对路径/确认过的产品方向.md"
```

文件须有唯一、非空且不嵌在 AUTO 中的 `[MANUAL]`／`[/MANUAL]` 区。
命令只将这个区保存到本实例的 `pilot-goals.md`，权限为 0600；
不会复制外部来源路径、AUTO 历史或其它实例配置。**MANUAL 正文本身不会自动脱敏**，
采用前不要在里面写凭据或不应进入模型上下文的资料。

这是原 `legion_pilot.py` 的上下文入口，不是新的指挥系统或质量评分器：

- 配置回执和 `check` 显示来源状态与文件摘要，不打印正文。
- 个人实例只读自己的方向文件；未配置或清除后保持为空，不回退旧仓或 Shell。
- 下次读取采用新内容；原有评价的继续分支选一条相关方向，最多 500 字，
  附到下一轮行动上下文。**不等于所有理念都已注入首轮或每个成员**；
  首脑直接决定继续的原分支也不保证经过这里。
- 方向不伪装成本轮用户新发言，不授予工具权限，不改变取消、模型绑定或成果导出边界。
  改动不会撤回已经发给模型的上下文，保存成功也不证明模型实际采用。

需要撤回时使用原配置入口；安全普通文件的正文损坏也可清除或重配：

```sh
.venv/bin/python -I meyo.py configure-goals \
  --state-dir "$HOME/.local/share/meyo-legion" --clear
```

清除长期方向不是取消正在运行的任务。来源或受管文件不符合文件权限、类型、
所有权、链接和大小要求时会如实拒绝，不借恢复操作放宽边界。

# 协作弯路：先找哪一段没有真正接上

这些方法来自对原生源码、适配链和既有交付记录的核对，用于决定下一步查哪里。
不把历史修复当当前全成员已验，也不把一次故障写成永久限制。
按症状只读相关小节；本文件不是新的runner、监督裁判或固定全家流程。

## 1. 平台说收到反馈，成员却没有改变行动

先区分**平台邮箱收到 → 原生循环取得正文 → 下一请求携带 → 成员实际采用**。
检查同一任务、会话与请求上的原始引用，不拿已读标记推导已送进模型。
原生机制有合法反馈入口就沿它接入，别把优秀Harness裁成普通问答接口。
请求已准备、实际发送及对应回执分开记录；只看到准备、发送失败或结果未知时，
不宣称投递已证，投递已证也不等于成员理解或采用。

复验时用同一段可辨认反馈追到真实后续动作。没有合法消息位置时保留待送达；
如果下一请求已经包含反馈，却没有改好作品，应继续查理解、工具和作品条件，
不能再一律归因“没收到”，也不能用反复加重提示词代替诊断。

查源起点：核心`team_state.py`、实际成员适配器，及对应原生Harness的
反馈入队和循环消费位置。Hermes的`steer`与conversation loop只是已存在的一种实现，
不是所有成员都必须模仿的接口。

## 2. 有任务名和断点，续作却像重新开始

**原任务引用、工程目录、合法身份、原生会话／断点**分别核对。
在原工程留可辨认的内容，续作后检查实际修改的是哪份文件、旧内容是否保留，
再走正式成果出口；模型说“我记得”不能替代这些事实。

有监督者指出正确目录、补图或提供反馈时记为监督介入，不宣称完全自主。
启动前失败、没有原生断点时，可以在允许的机制下开有来源的新轮次，
但不要叫恢复了不存在的断点。新身份也不能借旧任务权限继续。
发生误写不一定是底座丢字段，还可能是成员选错路径；先查证再确定根因。

查源起点：核心`project_context.py`与成员恢复入口，连接器`lib/client.js`的
工程绑定和`previous_task_ref`处理；部署恢复仍沿原实例，不用重新初始化假装修好。

## 3. 开发目录测试通过，用户拿到的包却不一样

冻结被采用的产物，追**制作源 → 构建／打包 → 安装／正式下载 → 实际入口**。
在真正的交付包中检查必需依赖，从这份包使用原入口；不要让测试偷偷借开发树文件。
正规源码包可能没有`.git`，目标环境也未必有大仓的历史工具和可编辑安装。

只测一个中间版本，不能替最终字节签收。最终作品改变后，补受影响的原旅程，
不必让所有作者从头重做；有效旧证据按版本和条件复用。
格式转换后保留来源关系，不假装转换后的hash仍应与原件相同。

查源起点：核心打包器、随包自检与正式资产出口；
媒体类另核消费者必需集合，不把“白名单允许WAV”当成“所需声音已经入包”。
缺失的历史测试如实记范围，不从大仓临时补进来后声称纯包已通过。

## 4. 有协议回包，被上层说成工具执行成功

保留**传输状态、工具执行状态、任务状态、业务结果**各自的语义。
对同一个原始失败回执比较包装前后：不能外层写成功、里面仍是协议错误，
也不能只抛一个异常而把可诊断的原结果丢掉。原生与auto入口分别查真实消费者，
不是只修工具列表或其中一条路径。

遇到共享预算，先从原计数持有者区分**暂时预占、已经结算的消耗、真正耗尽**。
在途占满不等于永久耗尽；非法或缺失用量保留未知，需要保守扣账时依据本次实际发送上限，
不把更大的预占额算成已花额度。新申请受限不能抹掉已经收到的在途结果；
执行成败、预算停止及取消／超时按原契约分别记录，不相互覆盖。

再沿实际链路逐层对照同一请求的公开事实：**产生端 → 原生返回 → 适配／HTTP／SSE → 持久结果与读取端**，
包括顶层和子结果的投影；回包成功不证明关键字段保留。用原函数的正常／失败对照定位哪层删了事实，
只补协议需要的公开字段，并验证隐私过滤仍有效；不透传整个对象，不加入私有 trace、原始流或凭据。

反例：评分器正常运行，却发现模型能力不合格，是有效的业务负结果；
不能见正文有`false`就判基础设施失败。修正错误传递也不等于网络恢复或文章已读到。
再做真实目标验证，协议测试只证明协议范围。

查源起点：工具桥的结果归一化、调用者如何处理原生错误，以及对应正常／失败回执测试。
字段名与嵌套以实际协议为准，不把某次检查名固化成跨项目放行名单。

### 命令行能用，日常入口仍然用不了

先核**实际运行快照、实例自己的目录、工具发现、HTTP身份、跨线程上下文和原生调用**。
开发候选的接口已存在，不等于用户常用的冻结版本已更新；不要为迁入一个接口覆盖整份旧模块，
丢掉现役版本的其他能力。保留原实例、身份、会话和能力，按影响面回迁并从实际入口复验。

HTTP会主动清除继承环境时，不能改成继承整个进程来“接通”，也不能接受正文提供的owner或目录。
需要本机私有实例的动作，只传当前已认证主体与可信运行配置核对后的必要引用，并验证另一用户、
空上下文和公网模式不能借用它。工具可直接调用后，还要从日常发现入口找到；旧摘要缓存不替代当前声明。

只读管理成功可能正好读到“暂停、未配置、没有来源”。把观察成功和接单能力分开，不删设置条件、
伪造身份或制造工单来凑闭环。查询也需要真实有界：文件类型检查不能放在可能阻塞的打开之后，
socket的单次空闲超时不等于整个响应的总时限；慢速头部、慢速正文和异常本机文件另用反例验证。

## 5. 成员done了，用户却没有拿到可用作品

运行结束、内容产出、授权导出、完整下载与用户实际使用是不同事实。
从该任务的正式出口取被登记的字节，核预期大小／hash，再打开下载物走主流程。
不要到工作目录另挑一份能用的文件替换验收对象，也不要文件变了后重算“预期hash”蒙混。

DSH Host下载成功不保证文件已经到浏览器用户的电脑，最后交接位置必须说清。
纯文字审查可以是有效贡献；但需要可玩项目时，审查文字不能代交项目。
导出失败不抹掉作者已做的工作，作者完成也不抵消导出缺口。

任务需要项目现场与正式导出时，对照**实际绑定 → 团队运行状态（TeamState）→ 项目事实（ProjectContext）→ 原出口**。
TeamState有节点不代表ProjectContext已有相同任务与真实成员归属；绑定完成后，应在执行／导出读取前
写回既有项目事实。沿原锁重新读取，只合并任务事实与必要元数据，保留并发新到的决定、产物、缺口、
工作区及owner／conversation，不用旧计划整体覆盖，也不再建一份平行账本。

查源起点：核心`project_context.py`的绑定写回、`artifact_delivery.py`与正式导出登记，
连接器`lib/client.js`的重新授权、字节校验与交付位置。任务描述和绑定事实不是授权来源；
跨owner／conversation、缺授权或撤权仍应拒绝。不能为消除导出拒绝放开根、扩大权限、换身份或扫未授权目录；
应先修正缺失的真实绑定，再从原入口复验。

## 6. 等回执时切了场景，旧结果污染了新现场

先认清状态归属：共享profile、当前会话、核心连接、具体请求和工作文件，
不一定具有相同寿命。晚返回的结果回到它所属的现场，不直接覆盖现在的配置或页面。

用可控制的返回顺序检查：A开始 → 切到B → A才返回；
分别观察成功、失败、卸载和回到A的恢复。不同实例／文件不需要全局串行，
也不能为防冲突把整个战队退化为一个线程。

工程合回只合已约定的写集，先比较基准与当前内容；有别人更新就重新读、合并，
不凭旧快照覆盖。用户停止等待与原生操作真正结束也要分开。
查源起点：连接器`client/index.js`的连接／身份归属、`lib/team-flow.js`的
原生修改顺序，以及旧回执晚返回的现有测试。

## 让经验真的回到战队

根因、修改条件、反例与复验结果归到相应能力或技能；具体版本、用户消息和运行记录留项目。
另一个成员能找到并实际采用，作品出现可解释的变化，才证明这项经验走到了使用环节。
笔记写好、工具可见、收到消息和多数成员同意都不能单独证明共同进化。

研究来源可沿连接器`docs/CORE.md`、`docs/ECOSYSTEM.md`、`docs/PLAN.md`
定位当前实现与历史事实，再到相关核心／原生源码；先核版本，不默认读取全部trace。
本次只更新技能时，只能验收技能与引用，不为证明这些方法擅自调用付费模型、重装或发布。

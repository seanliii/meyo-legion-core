## 保留现有程序，只补明确的 HTTPS 入口

```text
用户浏览器
  → 由运营者控制的固定 HTTPS 域名与证书
  → 同一云主机上的反向代理（保留实际 Host / Origin）
  → 127.0.0.1:8000 的原军团 server
  → 原个人身份、工程归属与原生执行路径
```

源代码、Python 环境和实例数据分离。代码固定到具体提交，服务用独立非 root 用户运行。
数据库、文件和原生断点保留在实例私有目录，不随源码更新覆盖。
模型凭据只按明确授权写入该云实例，不能自动复用开发机上的其他账号或公司凭据。

在原 `meyo.py` 中配置运营者实际控制的入口；下列域名仅为不可部署的文档示例：

```sh
.venv/bin/python -I meyo.py configure-public-origin \
  --state-dir /绝对路径/云实例 \
  --origin https://legion.example.invalid
```

此命令只修改已有实例的私有 `config.json`，不购买、部署或校验证书，不更换个人凭据。
服务依旧监听回环地址，`LEGION_ALLOW_REMOTE_BIND` 仍为 `0`。
运行中的服务不热更新；待本实例任务安全结束，再正常重启。

撤销合法配置：

```sh
.venv/bin/python -I meyo.py configure-public-origin \
  --state-dir /绝对路径/云实例 --clear
```

清除并重启后，不继承旧 Shell 的公网来源配置。
若配置文件本身损坏，命令仍拒绝运行；需由实例所有者修正配置并保留其余身份和数据，
而不是重新初始化或关闭检查。

## 同源与鉴权的边界

- 只接受明确配置的单一 HTTPS 来源；不接受通配符、凭据、路径、查询参数或控制字符。
- 公网请求的最后一跳必须来自同机回环连接，后台仍绑定回环地址。
- GET、POST 和 OPTIONS 共用公网模式检查；首页和合法分享不被改成必须登录。
- Host / Origin 重复、多值或不匹配直接拒绝；不靠 `X-Forwarded-*` 推断访问权限。
- 没有 Origin 的正常读取或 CLI 仍需通过原个人身份与资源归属检查。
- 公网模式签发的个人 Cookie 始终为 `Secure; HttpOnly; SameSite=Strict`。
- 本机管理和探活仍可用回环 Host；**公网代理必须拒绝访客伪造的 localhost Host**。
- 未启用此配置的旧本机及旧显式远程部署语义保持不变。

## 代理配置示意

可以复用 Caddy 等成熟反向代理，不增加另一个任务调度器。
下面仅说明匹配关系，不能原样当作已部署配置；实际域名、证书、监听与访问范围须在云端核定。

```caddyfile
legion.example.invalid {
    @configured_host host legion.example.invalid
    handle @configured_host {
        reverse_proxy 127.0.0.1:8000 {
            flush_interval -1
        }
    }
    handle {
        respond "Not Found" 404
    }
}
```

不把公网 Host 改写为 localhost，不移除 Origin，也不自动注入个人 Bearer。
HTTP 不进入业务后端；TLS 终止与证书有效性在外部真实访问时验证。
SSE 需要及时转发，不缓存整个响应、不用短代理超时截断长任务等待。
这份示意的语法与实际运行仍需在部署使用的代理版本上校验。

访问日志只保留必要路径、状态和耗时，不能记录 Authorization、Cookie、
请求正文、带票据的查询串或原生私有推理。不是把完整调试日志直接公开。

## 具体部署与运维顺序

1. 本人完成阿里云登录；检查已有资源，优先复用，不重复购买。
2. 核地域、系统、带宽、存储和税费后的实际价格，再确认开通。
   预算暂按每月不超过 300 元基础设施费；模型调用单独记账，不用试用优惠掩盖续费成本。
3. 部署固定源码与独立运行环境。先核真实原生 CLI 可执行，再配置获准模型；
   安装成功不等于模型或设备可用。
4. 配置 HTTPS、必要身份和运行隔离；不开放 Docker、ADB、VNC 或任意执行端口。
5. 从外部浏览器完成真实原始需求：登录→执行进度→成果→实际下载→反馈修改→刷新恢复。
6. 配置系统服务、只读健康检查、日志轮换和实例数据备份，做一次有记录的恢复演练。
   健康 200 不替代真实任务；持久配置不等于恢复演练通过。
7. 更新按“固定候选→相关验证→任务安全结束→切换→原旅程回读”执行。
   不在活任务上强杀、覆盖工程或从超时推断任务已结束；回退同时核代码、构建和数据兼容。

仅账号登录、实名认证／多因素验证、明确付费开通和必要权限变更由本人处理；
其余准备、执行、验收和记录由部署操作者完成。开通失败不重复扣费，先核平台实际资源状态。

## 本次验证能说明什么

新增回归通过真实回环 HTTP 连接调用原 Handler，覆盖配置来源、登录 Cookie、
已验证主体传递、伪造主体拒绝、错误 Host/Origin、控制字符和歧义主机、
首页、下载／分享／事件入口的来源检查；设备动作使用隔离替身，不启动设备。

这不是实际 TLS 反向代理、阿里云公网、SSE 长连接稳定性或多用户执行的验收，
这些仍须按上面的真实部署旅程完成。

代理行为参考：[Caddy 官方 reverse_proxy 文档](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)。

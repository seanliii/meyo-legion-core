# 个人运行验收说明

日期：2026-10-14。范围：macOS、单人私有实例、现有获授权模型接口。
不是公开 SaaS、全部成员认证或世界级交付声明。

## 用户已经可以做什么

1. 用自己的本地实例身份进入正常军团页面。
2. 提交真实任务，由原生 Codex 执行文件工具、生成 Markdown 和 HTML。
3. 在页面预览成果并下载文件。实际下载内容已与成员原文件逐字节核对。
4. 给同一成果反馈；成员读取反馈、使用原生专业工作室复核，并更新原文件。
5. 刷新页面或受控重启服务后，恢复原身份、历史、文件和原生会话。

本次实际需求来自用户对 OhMyGame 与军团源码、职责和协作机制的追问，
不是为验收临时编造的“输出一个字”。首版报告不当归因被指出后，
原成员通过受管 MCP 读回并接续 OhMyGame 的专用审阅会话，
交叉核对意见，再修改原 Markdown 和 HTML；新 Markdown 的浏览器下载已核对一致。

执行成员由本次操作员选择已配置的 Codex；工作室由用户指定 OhMyGame。
本次证明了真实委托、结果读取、反馈采用和原会话接续，
不证明军团已经自主选出了所有需求的最佳协作者。

## 当前运行接线

- 原有 `meyo.py init/configure-model/check/serve`，没有另造服务器或规划器。
- 个人模型配置和登录 Token 保存在源码外的私有实例目录，不进 Git。
- 实测的现有网关 Responses 地址以 `/v1` 为基础路径；
  曾经把 `/responses` 拼在 Chat 专用路径后得到的 404，不代表整个网关不可用。
  其他提供方必须使用自己真实支持的地址，不能盲套这一例子。
- OhMyGame 保留其自身模型配置与原生工作室；宿主能力通道不复制模型或个人 HTTP 密钥。
- `configure-capabilities` 只授权列明的现有动作。普通文件读写仍在原生命令沙箱内，
  需要宿主权限的能力通过 MCP 调到原 wrapper，保留完整的进程归属检查。

本次仍使用本人已经获准使用的现有模型网关。因此“代码和运行状态在个人环境”
不等于“已经完全不依赖该网关”。

## 本次真实失败如何处理

- 原生 shell 无法执行工作室的进程身份检查：没有删除检查或关闭沙箱，
  改为显式授权的宿主 MCP 执行原 wrapper。
- 初版工具参数只给空对象形状，实际原生成员反复发送空参数：
  改为明确的 `params_json` 字符串，解码后保留原校验；修后同一原生成员
  实际传入文件参数并完成工作室复核。
- 运行中“执行过程”入口被隐藏，直到结束才可见：
  已改为公开非心跳事件到达后实时显示，并尊重用户折叠选择。
- 徽标根据过程正文猜出“换模型、补位”：已改为只看结构化结果，
  不把用户问题和源码引用中的词当成已发生的成果。

这些修复针对已经撞到的运行与显示断点，不是增加领域规则或质量控制器。
此前中止的失败回合与原生历史保留，没有补写成成功。

## 使用与恢复

基本安装、配置和启动沿用根目录 README。先检查 `check` 的配置结果，
但是否可用仍须以真实任务为准。不要把密钥直接放在命令参数或提交进仓库。

需要宿主工作室能力时，按接入说明为个人实例明确授权所需动作。
改配置后先让当前任务结束，再正常重启服务；重启不能成为重复派单的理由。
恢复应使用原会话和原工程，调用受理不等于任务完成。

常驻部署应固定源码版本、Python 环境、实例目录和启动命令。
不同主机的执行环境分别验收；尚未核定个人承载环境时，不报告公网部署成功。

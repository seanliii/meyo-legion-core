# 个人账号与模型设置：已实现边界与接续

## 用户要得到什么

使用普通用户名和密码登录，在“我的模型与 Key”管理自己的配置。不再把手填长码作为默认入口；保留旧凭证兼容，不改变原 owner 的历史、文件、凭据和生效模型。

## 本次实现

- 在个人版启动器里指定独立账号存储位置及可信 owner；不改公司版部署。
- 注册用户获得随机内部身份；用户名不能抢占 owner。密码使用独立随机盐和 scrypt，登录 session 随机签发、仅存摘要、七天到期、可以退出撤销。
- 当前浏览器可使用旧码给本人首次设置密码；已有密码须校验当前密码才能修改。不会根据未认证用户名设置 owner 密码。
- `Secure / HttpOnly / SameSite=Strict` Cookie。仅回环本地测试允许非 HTTPS；账号写请求要求明确同源 Origin 和 JSON。
- 限制密码计算并发。只按用户名记录已完成的失败，成功清理；繁忙不算密码失败，不能耗尽一个覆盖所有人的长时间登录桶。
- 独立 Key 设置支持 DeepSeek、Moonshot、OpenRouter、自定义 HTTPS 接口。保存、列表、删除都以已认证用户为准；API 不返回 Key，不激活、不验证、不调用模型。
- 数据库位于个人运行目录的 `secrets/accounts/accounts.sqlite3`；目录 0700、文件 0600。这里是文件访问隔离，不声称已实现 KMS 加密或不同系统用户隔离。
- 公开成员目录仅返回静态画像，不按匿名 uid 读取历史、不返回私人入口、不触发探测；已登录 owner 仍走原有个人快照。

## 关键未完成：新用户实际执行

现有子进程复制实例环境，运行在同一个系统用户下。HTTP 身份隔离不足以防止代理工具读其他用户文件、秘密或继承 owner 模型。

因此新账号当前只开放登录和模型设置，不开放共享执行、原生工具入口、安装、恢复、模型探测或云设备。平台和前端明确展示这个状态；不能称“多用户军团已可用”，也不能将保存 Key 算作模型调用已验证。

下一阶段须沿原 runner 接入真实用户执行边界，而不是添加第二个答题器：

1. 为执行提供只含该用户资源的操作系统边界；不挂载整实例 home、secret、其他用户数据或宿主控制 socket。
2. 在本次调用的显式上下文绑定用户模型配置；不并发修改 `os.environ`，不得回退到 owner Key。
3. 同一身份贯穿原生执行、自动路径、工具、接力、恢复和成果回收。
4. 用两个用户与假提供方完成并发真实请求、读文件越权、失败接力和续跑验证；没有付费模型或云设备调用。
5. 通过上述验证后，才为对应用户开放已验证的执行能力，不一次性放开所有旧端点。

## 已验证

- 账号单测：密码/摘要存储、权限、撤销、过期、并发用户名、错误输入、两人 Key、限速及旧 owner 命名兼容。
- 真实本地 HTTP：注册、登录、Cookie、同源限制、旧码、owner 首次设置密码、新用户旁路拒绝、Key 列表和删除。
- 独立系统 Chrome + 浏览器沙箱 + 真实本地后端：注册 A → 保存假 Key → 刷新 → 退出 → 注册 B 无 A 配置 → 密码重登 A → 确认删除 → 原 owner 旧码登录 → 首次设置密码 → 密码登录仍为原 owner。桌面和手机视口截图，页面脚本异常为 0。
- 浏览器验收全部使用临时目录、假 Key；不读取生产 Key，不发模型生成请求、不启动付费设备。

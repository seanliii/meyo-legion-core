# 普通入口真实交付闭环：本轮执行与量化

## 唯一目标

> 普通军团入口也能自主发现关键体验问题、修改原成品、恢复真实未完，并把同一版本交到用户手里；
> 用原失败订单验证，而不是再写一份更长的规划。优化军团执行和监督，基于军团产出量化过程，不由操作者代做作品。

## 分工与范围

- 操作者只修通用运行、上下文、成果出口和计量；不编辑英语产品源码，不给成员填教学答案。
- 军团负责原品体验、参照选择、规划、实施、验证和返工。
- 复用本地候选`codex/code-parity-20261021`及原失败订单；公网、全局模型配置、其他在途订单不改。
- 已有反馈不得伪装成自主发现；观察者保留未提前告诉成员的行为检查。

## 执行顺序

1. 基于上轮已复现问题修现有产物导出、标准恢复入口、原生计量范围，各自先失败回归再修。
2. 用隔离本地标准服务接入真实旧订单/原工作目录与获准绑定；经普通HTTP/UI路径继续，不直接调用自制任务runner。
3. 跟踪实际原生动作、来源、决定、文件版本与交付；遇底层故障修故障，不替成员做产品。
4. 从用户入口检验实际产物；复验必须绑定同一入口/资源hash，并检查重启后仍可读/续作。

## 量化记录（观察，不作为平台固定门槛）

| 问题 | 记录事实 |
|---|---|
| 自主发现了什么 | 问题首次出现时间、已有反馈是否已包含、证据引用 |
| 是否真的返工 | 军团实际修改的版本差异、关联问题、复验结果；操作者产品改动数保持0 |
| 研究是否被采用 | 具名来源→具体决定→产物变化；搜索条数不算效果 |
| 是否持续执行 | 未完决定→实际下一调用/原任务恢复；成功节点是否被重跑 |
| 交付是否一致 | 用户下载字节与验证版本hash、资源可读、重启后可访问 |
| 是否更快更省 | 首次有用输出/首次可体验成果/修复耗时、可归属的原生用量、未知计量；不冒称账单 |
| 能力变化 | 原失败行为对照修后同路径，失败/退步如实保留，不以测试总数替代提升 |

本轮成功必须有普通入口的真实旅程与军团实际作品变化。仅代码测试、文件登记、模型回复done或写完本文件都不算完成。

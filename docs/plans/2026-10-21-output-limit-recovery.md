# 输出截断：同任务恢复、真实状态和用量保真

日期：2026-10-21（Asia/Shanghai）。

本次仅本地候选与本地用户需求验证，未部署、未推送到公网，未改变公司或个人线上模型配置。

## 原始问题和证据

实际英语学习产品请求通过既有 `dispatch_persistent → run_one → Codex CLI`，
使用已授权公司 GLM-5.3。前三轮保留相同原生线程和工作目录，但每轮最终收到
`Incomplete response returned, reason: max_output_tokens`，没有可用页面。
旧分类为 `process / retryable=true`，外层继续原样派发。

本机已安装原生 CLI 的只读沙箱＋回环假服务验证：

- 原生请求没有 `max_output_tokens/max_tokens` 字段。
- 假服务的 `response.incomplete` 提供了 usage，但 CLI 映射出的 `turn.failed` 没有保留数字。
- 输出不完整不等于工具没执行。对于已收到完整合法参数、已完成分发的工具，工具可能执行成功，随后整轮才失败。

两个极小的真实同提供方调用只验证了接口接受显式 `max_output_tokens=128`；
默认响应没有报告实际输出预算。**没有证据证明复杂任务应该设置成128，或者默认上限是多少。**
本次不杜撰默认预算、不关闭绑定校验、不引入代理或修改已安装 CLI。

## 修复范围

### 1. 类型明确，原始事实保留

`error_envelope.output_limit_from_native` 只消费可信终态：
Codex 的精确 `turn.failed` 或 Responses 的结构化 `response.incomplete`。
不扫描用户答案、工具输出或文档中的关键词来判错误。

`output_limit` 与输入超窗、HTTP限流、进程故障分开。上游未给预算/用量时仍为未知。
工具执行到哪里，以原生工具结果与现场读回为准，不原样重放未确认的操作。

### 2. 恢复信息进入真实调用

`run_one` 在原 checkpoint 已落盘、调用方预算允许且同一输出恢复尚未尝试时，
通过原 `prior_attempts/task_memory` 通道给同模型、同凭据、同线程、同目录一次恢复机会。
提示说明输出截断的事实及已完成边界需核验，不强制业务制作路线。

原 `prior_attempts` 文本投影漏了结构化错误里的恢复说明；现在将有限白名单字段带入
实际 Codex stdin。相关测试经过真实 adapter 与原生输入构造，不只断言字典里存在。

再次同样失败、checkpoint缺失或恢复现场写入失败时，保持失败和恢复引用，
暂停旧请求的原样自动重试，不切模型、不把空 final 当作“没有执行/没有花费”。

### 3. 重启与依赖恢复也读暂停事实

`team_state.recoverable_tasks/list_auto_resumable/claim_resume` 读取已持久化的输出暂停事实。
单一暂停任务不会因为服务重启又获得一轮重试；混合任务的独立分支可以继续。

`resume_plan_from_state` 保留涉及暂停节点的相关任务图，不把未满足依赖删除成无依赖。
后台恢复和既有 `/team/resume` 从可信状态读取结果，经现有私有 `_retained_results` 通道传递。
暂停任务的原执行者、checkpoint与失败记录不改成重新选人或成功。

依赖语义复用原有 all_succeeded/all_finished/any_succeeded，不重新发明策略。
`all_finished` 的审查任务可消费已结束失败事实，不把所有后继一刀切禁用。

这是旧请求的暂停，不是用户、模型或会话的永久封禁。用户明确调整条件后，可发起新的
请求流水号，同时保留原 conversation、工作目录和原生线程，仍经过已有 provider 绑定检查。

### 4. 用量未知不是零

每个实际执行过的 native attempt 均登记用量记录；`None`、缺失和空字典按未上报保留。
不把调用前拒绝计入已执行次数。聚合、成员汇总、结果卡都保留：

- `complete / coverage`
- `attempts_total / attempts_reported / attempts_unreported`
- 已知输入/输出/费用小计

不能从末次成功数字推导整单总消耗。原生 CLI 已丢失的真实数字不能靠父层补算；
精确恢复这些数值仍需要原生终态协议保留完整元数据。

## 验证

- 真实临时 Git 用例验证同步引入的自动提交不卷入用户 index、其他文件、目录或符号链接；
  这属于同候选的代码追平保护，不是输出预算修复本身。
- 完整本地 Python 回归：**1224 passed, 5 skipped**；跳过项不算通过。
- 全部本地 JavaScript 回归：**90 passed**，包含显式沙箱浏览器测试和用量部分已知文案。
- 重启/混合依赖/人工改条件续接验证使用实际状态读写、server恢复函数、
  dispatch/run_one和原adapter，模型边界为明示离线替身。
- 原真实 GLM 线程由操作者带失败现场发起恢复后，实际生成43个应用文件，包括HTML、
  JavaScript、CSS与37个音频文件；模型仍为GLM-5.3，原线程和目录一致。
- 这次真实恢复是**操作者发起**，不是修改已经运行完的旧进程而产生的全自动修复。
  不能把它误称为军团未经提醒就自主发现并修好了所有问题。

## 用户作品验收边界

成员原生浏览器遇到 macOS Mach-bootstrap 权限错误，使用了替代视觉预览。
替代预览不算真实页面验收，不因它说 status=done 就判用户目标完成。

父对话在应用内真实打开本地页面，完成演示档案、首日入口、错误选项、正确选项、
进入识词和口语页，并在第二标签看到同一档案保存。
家长确认步骤出现浏览器控制通道超时，无法据此判定产品故障或确认完整通过。
未请求真实儿童录音，未宣布口语自动评估、三天学习、家长完整闭环或世界级美术通过。

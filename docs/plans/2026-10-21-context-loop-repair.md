# 2026-10-21：把真实现场接回原任务，而不是新增质量裁判

## 本轮问题和边界

用户问：“loop 为啥没有发现问题，军团咋回事，明显不对，上下文机制哪里出了问题。”

仅修改本地候选，公网版本、个人模型绑定、真实儿童数据均不动。
英语作品是回放样本；不是把军团改成教育专用流程。

## 已有事实

1. 原任务三次输出截断时，原持续调用方知道没有完成。操作者随后直接调用 `run_one` 恢复，
   因而恢复的是执行，不是任务级体验循环；不能把它描述成原 loop 自主完成了交付。
2. 单成员服务入口已经消费 `coordinate: continue`，持续派发入口却没有消费同一请求，
   会把本轮 `done` 覆盖到仍未完成的任务上。必须打通同一协议，而不是再建一个控制器。
3. 同一项目的稀疏续作会清空部分验收要求、体验意图、观察和 Gap。旧文件仍在，
   不代表下一次调用实际拿到了这些事实。
4. 历史经验根据关键词自动展开，否定句中的“游戏化”也会把旧游戏要求注入教育任务。
5. 本地原生成员的浏览器未接入已有受管通道；图片落盘后，文本输入模态仍拒绝看图。
   原有视觉工具又因隔离 HOME 找不到模型目录，返回 `media_direction_unavailable`。
6. 原线程多次 `update_goal` 返回“没有 Goal”；工具错误确实回到了历史，但成员仍重复调用。
   Meyo 的目标文本与 Codex 的原生 Goal 不是同一对象，不自动为普通任务创建第二套 Goal。

## 修改方向

- 历史经验默认只给短索引，由当单明确选择后再展开；保留原始记录。
- 同一成员自己的续作意图统一传给现有 Pilot，重开原节点并保留线程、目录和实际状态；
  不授予该成员修改全队计划的权限，不绕过暂停、取消或预算。
- 稀疏恢复保留项目的真实质量现场；明确的新意图仍可更新，不跨用户继承。
- 复用 `LEGION_FRONTIER_CONTEXT → record_result → snapshot`，保存成员实际回传的资料、
  采用理由、体验观察和未完事项，并保留原始报告及出处。
- 成员自报、独立复核、运行事实并列保存。自报不是全局质量证明，也不因缺少另一名裁判
  就禁止成员更新自己缺口的状态。
- 本地原生成员复用已有受管浏览器。仍使用原生命令沙箱；源码、宿主控制目录、浏览器材料
  不在任务写范围内；临时能力随调用结束回收，不借用用户正在使用的浏览器。
- 原生模型的输入模态按本次真实目录声明暴露，不擅自把文本模型声明成视觉模型。
- 媒体工具使用操作者明确传入的授权目录；引用不可用时报错，不借别的 HOME 或缓存中的授权。

## 验收不偷换

离线回归需要证明：

- 同一未完请求在 single 和 persistent 两条入口均能续作；合法短答仍单轮结束。
- 真正重开已完成节点，下一次执行不是重复读取旧结果，原生会话范围不变。
- 旧观察和缺口在下一次真实快照中仍可读；新报告不覆盖别人或独立复核的事实。
- 改变 HOME/cwd 不丢明确授权引用；失效引用不导致凭据回落。
- 浏览器仍受管、无全局沙箱降级，控制凭据不进入命令行或提示词。

真实回放还需要证明：

- 浏览器能打开原作品、真实点击、返回实际截图，并完成资源清理。
- 图像理解工具真正消费截图；有目录、有模型名不算看图成功。
- 原成员收到实际缺口后，修改原工程并再次体验；操作者不手改作品冒充自主返工。
- 未完成、预算暂停、真实阻断如实保留。`done`、通过测试和生成报告都不证明世界级体验。

## 未解决的范围

本次不证明所有成员普遍优于单家，不证明教育有效性或真实连续三天的儿童使用效果。
普通成员仍可能不研究、不使用已授权工具或错误判断质量；需以真实调用、作品差异和体验证据
判断改动是否有效，不能以“配置已接通”宣称通用质量循环已经完成。
